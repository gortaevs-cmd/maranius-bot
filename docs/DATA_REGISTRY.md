## `/tmp/maranius-health.json`

Эфемерный технический статус внутри контейнера, права 0600; не пользовательские
данные и не часть runtime-backup. Версия 1: `pid`, `process_start` (Linux starttime
процесса), `updated_monotonic`, `ready`, `reasons`, `queue`. В `queue` только
счётчики `pending`, `sent`, `failed`, `expired`, `due`, `oldest_due_seconds`;
тексты уведомлений, ID получателей и токены не записываются.

Один watchdog процесса бота обновляет файл примерно каждые 10 секунд после
успешной проверки хранилища либо сразу с `storage_unavailable` при ошибке.
Простой I/O/event loop оставляет последний снимок устаревать; после 90 секунд
probe возвращает ошибку. PID и starttime защищают от принятия статуса старого
процесса. При штатной остановке записывается `ready=false`.

`python scripts/check_health.py` читает только этот файл и `/proc`; не импортирует
бот/хранилище, не восстанавливает JSON и не вызывает API. Проверка рабочего
хранилища и штатный replay журнала выполняются только основным процессом под
его общим storage lock.

## `legacy_inactive_users.json`

**Статус:** реализовано (`integrations/legacy_contacts.py`); в production лежит в `/app/.runtime` и исключён из Git.

Отдельный минимальный список старых контактов, которых нет в верифицированной выгрузке доставки и которые не имеют VIP. Запись: `id`, `source`, `listed_at`. Эти записи не становятся пользователями Maranius и не входят в маркетинговые сегменты. После возвращения в бот и принятия актуальных согласия на ПДн и пользовательского соглашения ID атомарно удаляется из этого списка, профиль сохраняется активным в `users.json`, а seed-админу уходит одно уведомление.

Перед production-деплоем в том же runtime можно положить только-ID манифест `legacy_migration_pending.json`. Новый процесс бота применяет его до запуска polling, пишет результат вместе с манифестом в `legacy_migration_last_result.json` и удаляет pending-файл. Это исключает гонку с обычными обновлениями `users.json`.

## `consent_log.json`

**Статус:** реализовано (`integrations/consent_log.py`); в production лежит в `/app/.runtime`.

Append-only журнал согласий и акцептов. Запись: `id`, `created_at`, `user_id`, `event`
(`policy_accepted`, `user_agreement_accepted`, `marketing_opt_in`, `marketing_opt_out`), `value`, `purpose`,
`document`, `policy_version`, `document_url`, `action`, `source`, `meta`. Так фиксируются
назначение, редакция документа, URL и конкретное активное действие пользователя.

Retention: **365 дней**, максимум **50 000** записей. Текущие поля в `users.json` — кэш
для сегментов; юридически значимая история — в этом журнале. В `/god → Журнал действий`:
последние 10 записей и CSV-выгрузка.

## `notification_outbox.json`

Runtime-файл (`/app/.runtime` в production), исключён из Git и Docker image.
Создаётся при первой постановке уведомления; старый Inbox не импортируется.
Права нового файла/backup — 0600, штатный runtime-backup включает его автоматически.

Корень: `version: 1`, `items[]`, `next_allowed_at` (общий RetryAfter).
Событие: `id`, `key`, `payload_hash`, `created_at` (Unix UTC), `text`, `parse_mode`,
`inbox_id`, `state` (`pending/sent/failed/expired`), `completed_at`, `ack_next_at`.
В `recipients[]`: `id`, `state`, `attempts`, `next_at`, `error_type` (только имя типа).
`next_at` перед отправкой служит lease; записанный `sent` запрещает повтор этому
получателю. Источник Inbox отмечается только после успеха всем получателям.

1000 ожидающих, до 2000 завершённых, 7 дней ожидания/истории в основном файле,
20 попыток. Текст удаляется после завершения/истечения; JSON backup хранит до
10 предыдущих версий независимо от возраста. Очередь предназначена только
для текстовых уведомлений владельцам, без автоматической рассылки старых записей.

JSON-слой сохраняет исправную предыдущую версию перед заменой и атомарно
восстанавливает повреждённый файл; ошибки backup не пропускаются. Для активности,
Inbox, платформенной базы, журналов согласий/админ-действий/групповых событий,
VIP-кодов и legacy-списка полные операции выполняются в потоке под async lock.
Обработчики реестра пользователей также вызывают его синхронный API через
`run_storage_io`, удерживая общий users lock от чтения до окончания записи.
Отмена задачи дожидается завершения дисковой операции перед освобождением lock;
при погашении VIP-кода — также выдачи доступа или штатного rollback при ошибке.
Связанные операции источника/очереди, согласий/журнала и админ-изменений/аудита
выполняются через `atomic_json`; отдельные JSON остаются прежними.

## `storage_transaction.json`

Временный runtime-журнал с правами 0600, исключён из Git/Docker context.
Создаётся только для новой транзакции. Корень: `version: 1`, `writes[]`, `sha256`.
Запись `writes[]`: абсолютный путь `path`, новое JSON-значение `data`, флаг
`trailing_newline`. До 16 файлов; данные фиксируются одним решением перед
изменением источников. Журнал может временно содержать полные снимки users,
согласий, аудита, VIP-кодов и очереди; его нельзя считать обезличенным логом.

До journal commit ошибка отклоняет всю операцию. После commit незавершённое
применение повторяется до любого следующего чтения/записи. Все обращения к
хранилищу в одном процессе сериализуются, включая обычные RMW операции.
Невалидный JSON участвующих файлов не заменяется автоматически отдельным старым
backup, чтобы не откатить только часть общего изменения. Нужен целый согласованный
снимок. Повреждённый журнал, неверная checksum или путь вне допустимых корней блокируют
replay; частичное состояние не возвращается. При успешном завершении журнал
удаляется с fsync директории. Ошибка cleanup также не разрешает новую операцию
до подтверждения устойчивого удаления.

Новая схема объединяет Inbox+outbox, первый визит/legacy+outbox, VIP-код/права/
outbox, согласия/документы, настройки и отзыв маркетинга, админ-изменение/аудит,
агрегаты отчётов/outbox и результат legacy-миграции/outbox. Старые данные не
пересчитываются; история Inbox не превращается в задания автоматически.

Backup создаётся при приостановленном writer и включает журнал целиком при его
наличии. Восстанавливать нужно полный снимок runtime/data. Откат при pending-
журнале требует образ с поддержкой версии 1; helper проверяет label совместимости
после остановки writer. Внешняя доставка Telegram по-прежнему как минимум один раз.
