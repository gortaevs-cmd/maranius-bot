## Блок 1 — доступ, очередь сообщений и резервное копирование

Подготовлено:

- VIP-callback, включая старые кнопки, проверяет ручную блокировку и обе актуальные
  версии обязательных документов перед проверкой VIP.
- VIP-материалы, ввод кода и административные операции доступны только в личном
  чате. Административный режим ввода не переносится из личного чата в группу.
- `my_chat_member` обновляет существующий профиль владельца личного чата, а не
  профиль самого бота. Служебное событие не создаёт новый профиль до согласий.
- При удалении webhook и запуске polling накопленные updates сохраняются.
- VIP-редактор больше не передаёт `protect_content` в неподдерживающий его
  `edit_text`; защита сохраняется на исходном сообщении и при новой отправке.
- Backup включает существующий `.runtime` и `data`; перед первой миграцией —
  старые `users.json` и `admins.json`. Отсутствие необязательных старых файлов не
  мешает копированию. Ошибка архивации или отсутствие обязательного файла
  останавливают деплой. Неполная копия не подменяет предыдущую проверенную.
- Ошибка до начала замены контейнера не вызывает его перезапуск через rollback.
- Runtime-каталоги и журналы дополнительно исключены из Docker build context.
- Тесты запускаются во временной копии без локальных секретов и рабочих данных;
  сетевые подключения запрещены. CI использует тот же запуск.

Проверка: 119 тестов успешно прошли локально на существующем Python 3.9.6.
Проверен синтаксис shell-скриптов. Docker, shellcheck и Python 3.12 локально
отсутствуют; контейнерная сборка, dependency audit и среда Python 3.12 остаются
проверками GitHub Actions. Отдельный lint/typecheck в проекте пока не настроен.

## Блок 2 — достоверность доставки и безопасная диагностика

Подготовлено локально, без второго обновления production:

- Inbox отмечается уведомлённым только после успешной отправки всем настроенным
  получателям. Пустой список и частичная неудача не считаются доставкой.
- Общие текстовые уведомления владельцам повторяются при NetworkError/TimedOut и
  коротком RetryAfter: максимум 3 попытки, сетевые тайм-ауты ограничены. Forbidden,
  BadRequest и неожиданные ошибки не повторяются. RetryAfter больше 5 секунд
  возвращает неуспех, чтобы не держать пользовательский обработчик в ожидании.
- Лимит Inbox по пользователю сохранён; кэш предыдущей минуты очищается, чтобы не
  накапливать ключи всех пользователей за всё время работы.
- Новый `integrations/diagnostics.py` пишет только тип ошибки, технический update_id,
  номер попытки и файл/строку/функцию. Текст ошибки, полный update, локальные
  переменные и URL запросов не выводятся. Администратор получает тип ошибки.
- Опасные выводы исключений удалены из обработчиков, уведомлений и утилит smoke/PDF;
  proxy URL с возможными учётными данными больше не печатается.

Ограничения: это короткие повторы внутри процесса, а не постоянная очередь доставки.
После исчерпания попыток запись остаётся неуведомлённой в Inbox; автоматическая
отложенная доставка после длительного outage требует отдельного блока. Старые записи
не рассылаются повторно. После сетевого тайм-аута возможен дубль — Telegram не даёт
ключ идемпотентности для sendMessage.

Проверки блока 2: 139 изолированных unit-тестов прошли (20 новых проверок),

1. При необходимости — постоянная очередь отложенных уведомлений с контролем
   повторов после перезапуска. Базовые исправления доставки и логов готовы в блоке 2.

   Перенос кода и изменение поведения выпускать отдельными коммитами.
4. Хранение и нагрузка: длительные отправки, синхронные JSON-операции, восстановление
   незавершённых связанных записей, пределы памяти и качества healthcheck.
5. До включения рефералов: ключ идемпотентности списания наград и дополнительные
   проверки повторных запросов. Механика остаётся отключённой.

Откат образа не откатывает пользовательские JSON. При необходимости восстановления
данных требуется отдельная согласованная операция, а не автоматическая подмена
всех файлов предыдущей копией.
